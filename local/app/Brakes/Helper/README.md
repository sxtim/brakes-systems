# Image Helper & Migrator

В каталоге лежат хелперы, которые работают с фотографиями товаров.

## Файлы

- `Image.php` – общий хелпер, в котором собраны пресеты ресайза (`PRESET_CATALOG_TILE`, `PRESET_PRODUCT_GALLERY_MAIN`, `PRESET_PRODUCT_GALLERY_THUMB`). Здесь задаём размеры и качество.
- `ImageMigrator.php` – сервис, который переносит ссылки из старого строкового свойства `LINK_PHOTO` в файловое `LINK_PHOTO_FILE` и готовит данные для кеша Bitrix.

## Точка входа (CLI / cron)

Запуск мигратора: `local/cron/image_migrator.php`

```bash
php local/cron/image_migrator.php --start-id=0 --chunk=200
```

Поддерживаемые флаги:

- `--id=<ELEMENT_ID>` – миграция конкретного элемента.
- `--start-id=<ID>` – начать обработку с указанного ID.
- `--chunk=<N>` – количество элементов за итерацию (по умолчанию 200).
- `--limit=<N>` – сколько всего элементов обработать (0 = весь каталог).
- `--dry-run` – проверка без фактической записи файлов.
- `--force` – перезаписывать данные, даже если `LINK_PHOTO_FILE` уже заполнен.
- `--delete-source` – удалять исходники из `/fotoz` после успешного переноса.

## Процесс

1. 1С или редакторы загружают исходники в `/fotoz` и прописывают путь в `LINK_PHOTO`.
2. Запускаем мигратор (вручную или по cron) – файлы копируются в `/upload/iblock/...`, свойство `LINK_PHOTO_FILE` заполняется ID файлов.
3. Шаблоны выводят изображения через `Image::resizeByPreset()`. После смены настроек пресета очищаем `/upload/resize_cache/iblock` (или через админку «Очистить кеш миниатюр»), чтобы Bitrix пересоздал миниатюры.

## Остатки и цены (1С)

Остатки и цены приходят **только через обмен 1С**, парсер и мигратор их не трогают.

### Файлы обмена

- `import___*.xml` — номенклатура/свойства.
- `prices___*.xml` — цены.
- `rests___*.xml` — остатки (`ПакетПредложений/Остатки`).

Важно: если в `rests___*.xml` стоит `СодержитТолькоИзменения="true"`, то файл содержит **только часть** товаров (изменённые). Остальные остатки не обновляются и остаются старыми/нулевыми. Для полной синхронизации нужен `СодержитТолькоИзменения="false"` или регулярный полный обмен.

### Что делает наш парсер

`local/cron/1c_catalog_parse.php` работает **после** выгрузки 1С и:

- раскладывает товары по разделам;
- обновляет активность веток;
- заполняет служебные свойства (`OEM_NUMBERS`, `PRODUCT_CATEGORY`);
- обновляет фасетный индекс.

**Цены и остатки он не обновляет** — это зона стандартного обмена 1С (`prices` / `rests`).

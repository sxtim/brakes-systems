# Оплата, доставка и чеки

## Текущее состояние на 13.05.2026

- MVP-флоу заказа работает: заказ создается без оплаты, менеджер переводит заказ в `Ожидает оплаты`, формируется ссылка, оплата проходит через T-Bank.
- T-Bank используется только как эквайринг. Передача данных для чека в T-Bank выключена.
- Bitrix получает callback от T-Bank и отмечает платеж оплаченным.
- Orange Data подключена через стандартную кассу Bitrix и успешно пробивает чек после оплаты.
- В чек уходит только товарная позиция, доставка в чек не попала.
- Открытый вопрос: НДС товаров сейчас в тестовом чеке ушел как `Без НДС`; настройку НДС 5% разбираем отдельным этапом.
- CDEK API, Bitrix24, 1C-синхронизацию заказов и личный кабинет пользователя сейчас не трогаем.

## Общий план

Цель: сначала сделать рабочий контур в Bitrix: заказ -> согласование -> ссылка на оплату -> оплата -> чек по товарам. После этого подключать Bitrix24 и 1C по заказам.

### Этап 1. Bitrix, доставка, оплата, чек

- Клиент оформляет заказ на сайте.
- Оплаты сразу нет.
- Товар с остатком `0` можно заказать, на сайте пишется `Под заказ`.
- Заказ создается в админке Bitrix.
- Доставка выбирается или рассчитывается и сохраняется в заказе.
- Менеджер смотрит заказ в Bitrix.
- Менеджер согласовывает заказ с клиентом.
- Менеджер при необходимости меняет состав, количество, цены, доставку.
- Менеджер переводит заказ в статус `Ожидает оплаты`.
- Bitrix формирует ссылку на оплату.
- Менеджер отправляет ссылку клиенту в мессенджер.
- Клиент оплачивает через Т-Банк.
- Bitrix отмечает оплату.
- Orange Data отправляет чек только по товарам.
- Доставка в чек не идет.

### Этап 2. Bitrix24

- Новый заказ из Bitrix уходит в Bitrix24.
- В Bitrix24 создается сделка или заказ.
- Передаются клиент, телефон, email, товары, сумма, доставка, комментарий.
- В Bitrix24 появляется ссылка на оплату после согласования.
- После оплаты Bitrix обновляет статус в Bitrix24.

### Этап 3. 1C по заказам

- Новый заказ из Bitrix уходит в 1C.
- В 1C передаются товары, количество, клиент, телефон, доставка.
- 1C возвращает номер заказа или документа.
- Если менеджер правит заказ в 1C, изменения должны вернуться в Bitrix перед оплатой.
- После оплаты Bitrix передает факт оплаты в 1C.
- Остатки по-прежнему приходят из 1C на сайт.

## Чеклист первого этапа

### 1. Оформление заказа

- Проверить, что заказ создается в Bitrix Sale.
- Убрать оплату из стандартного оформления.
- После оформления показывать понятный текст: `Заказ принят, менеджер свяжется с вами для согласования`.
- Не открывать Т-Банк автоматически.
- Не показывать кнопку оплаты на финальном шаге оформления.
- Проверить, что заказ с товаром `Под заказ` создается без ошибок.

### 2. Остатки

- Остаток больше `0` -> показываем `В наличии`.
- Остаток `0` -> показываем `Под заказ`.
- Остаток `0` не блокирует корзину.
- Остаток `0` не блокирует оформление заказа.
- Бронь на сайте не делаем.
- Остатки не уменьшаем вручную после оформления заказа.

### 3. Доставка

- На первом этапе клиент выбирает только тип доставки.
- Стоимость доставки на сайте не рассчитывается.
- Стоимость доставки в онлайн-оплату не входит.
- Доставка в чек не уходит.
- Менеджер после оформления отдельно согласует доставку с клиентом.
- CDEK API на первом этапе не нужен.

### 4. Статусы заказа

- Новый заказ получает статус `Новый / На согласовании`.
- Добавить статус `Ожидает оплаты`.
- Оплата доступна только в статусе `Ожидает оплаты`.
- После успешной оплаты заказ и платеж становятся оплаченными.
- Не давать оплатить заказ, который еще не согласован.

### 5. Ссылка на оплату

- Сделать страницу оплаты `/personal/order/payment/`.
- Ссылка должна открывать оплату конкретного платежа.
- Ссылка формируется из Bitrix-заказа, не вручную в Т-Банке.
- Перед созданием ссылки сумма платежа должна быть актуальной.
- Если менеджер поменял заказ, старую сумму нельзя использовать.
- Менеджер должен понятно видеть и копировать ссылку.

### 6. Т-Банк

- Платежная система подключена.
- Рабочий терминал внесен.
- Передача данных для формирования чека в T-Bank выключена.
- В Bitrix у платежной системы включено `Разрешить печать чеков`.
- Проверена оплата 1 рубль.
- Проверить успешный callback.
- Проверить неуспешную оплату.
- Проверить, что повторная оплата оплаченного заказа невозможна или не ломает заказ.

### 7. Orange Data

- Касса настроена: ФФД 1.05.
- СНО: УСН доход.
- НДС товаров: 5%.
- Email: `sales@shinylight.ru`.
- ОФД: Платформа ОФД.
- Рабочую кассу другого сайта не трогать.
- Доставка в чек не уходит.
- В чек уходят только товары.
- Проверен чек после оплаты 1 рубль.
- Открыто: добиться НДС 5% в товарных позициях.

### 8. Проверки перед сдачей этапа 1

- Заказ с товаром в наличии создается без оплаты.
- Заказ с товаром `Под заказ` создается без оплаты.
- Смешанный заказ создается без оплаты.
- Менеджер может поменять состав заказа.
- Менеджер может поменять сумму.
- Менеджер может поменять доставку.
- После статуса `Ожидает оплаты` ссылка работает.
- До статуса `Ожидает оплаты` ссылка не дает оплатить.
- Оплата проходит через Т-Банк.
- После оплаты Bitrix видит платеж как оплаченный.
- Чек уходит в Orange Data.
- В чеке нет доставки.
- Сумма чека равна сумме товаров.
- Сумма онлайн-оплаты равна сумме товаров.
- Ошибки оплаты и чека логируются.

## Что важно не забыть

- Не делать сейчас сложную синхронизацию с 1C и Bitrix24.
- Не делать автоматическую бронь.
- Не делать частичные оплаты.
- Не включать доставку в чек.
- Не включать доставку в оплату без отдельного подтверждения.
- Сначала сделать стабильный центр: `Bitrix заказ -> платеж -> Т-Банк -> чек`.
